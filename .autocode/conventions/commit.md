# Commit messages

Conventional Commits with an optional issue scope. The shape mirrors the PR title format auto-generated by `.github/workflows/pr-autofix-title.yml`, so commits and PR titles read consistently.

## Subject

`<type>(#<issue>): <subject>`

- `type`: one of `feat`, `fix`, `docs`, `refactor`, `ci`, `chore`, `release`, `test`, `deps`, `perf`.
- `(#<issue>)`: optional. Include the GitHub issue number when one exists; omit the parentheses entirely otherwise.
- `subject`: imperative mood, capitalize the first word, no trailing period, hard cap 72 chars (aim for 50).

## Body

- Separate from the subject with one blank line.
- No manual line wrapping; let the renderer wrap.
- Include a body only when the "why" is not visible in the diff. Required for breaking changes, security fixes, data migrations, and reverts.
- Do not write "This commit ...", "I/we ...", "as requested by ...", or AI attribution.
- Co-authors via a `Co-authored-by:` trailer.

## Examples

- `feat(#12): Add clone-step idempotency check`
- `fix(#47): Refuse to clobber differing AUTOCODE_CONFIG_DIR`
- `chore: Bump plugin version to 0.2.0`
- `refactor(#103): Split provider dispatcher into resolver and runner`
